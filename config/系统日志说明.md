# 系统日志说明

本文档描述 PointCloud 应用程序写入磁盘的**结构化系统日志**（JSONL 格式），便于离线分析、Python 脚本自动化提取与绘图。

---

## 1. 概述

| 项目 | 说明 |
|------|------|
| 格式 | **JSON Lines（JSONL）**，一行一条 JSON 记录 |
| 编码 | UTF-8 |
| 时间 | 字段 `ts` 为 **UTC**，ISO 8601，含毫秒（例：`2026-05-20T06:32:01.123Z`） |
| 写入方式 | 后台线程异步写盘，不阻塞检测与 UI |
| 与 UI 日志关系 | 界面「检测信息」「设备状态」面板**独立**；系统日志仅写文件 |

---

## 2. 文件位置与命名

- 默认目录：程序运行目录下的 `logs/`（可在 `config.json` 中修改）
- 文件名：`system_YYYY-MM-DD.jsonl`（**按自然日滚动**，UTC 日期与本地日期在跨零点时以系统本地日期为准）
- 示例：`logs/system_2026-05-20.jsonl`

Release 运行时，若通过 CMake 部署，`config.json` 与可执行文件同级；`logs/` 目录会在首次写入时自动创建。

---

## 3. 通用字段

每条记录均包含以下字段（除特别说明外）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ts` | string | UTC 时间戳 |
| `level` | string | `DEBUG` / `INFO` / `WARN` / `ERROR` |
| `tid` | number | 写入时所在线程 ID（Windows 为系统线程 ID） |
| `module` | string | 模块名（如 `Sensor`、`BerthDetection`） |
| `event` | string | 事件类型，用于过滤与解析 |

各事件在通用字段之外携带的业务字段见下文。

---

## 4. 配置项（config.json → system_log）

```json
"system_log": {
  "enabled": true,
  "dir": "logs",
  "retain_days": 14,
  "min_free_gb": 5.0,
  "cleanup_on_startup": true,
  "sensor_fps_interval_sec": 5,
  "disk_check_interval_sec": 600
}
```

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `enabled` | `true` | 是否启用磁盘系统日志 |
| `dir` | `"logs"` | 日志目录，可为相对路径（相对程序目录）或绝对路径 |
| `retain_days` | `14` | 超过该天数的旧日志文件自动删除 |
| `min_free_gb` | `5.0` | 日志所在磁盘剩余空间低于此值（GB）时触发额外清理 |
| `cleanup_on_startup` | `true` | 程序启动时是否执行一次过期日志清理 |
| `sensor_fps_interval_sec` | `5` | 传感器帧率汇总周期（秒） |
| `disk_check_interval_sec` | `600` | 磁盘空间检查周期（秒，即 10 分钟） |

---

## 5. 事件类型说明

### 5.1 `logger_started` — 日志系统启动

**模块：** `SystemFileLogger`  
**时机：** 程序加载配置并成功初始化日志后  

**附加字段：**

| 字段 | 说明 |
|------|------|
| `log_dir` | 实际使用的日志目录绝对/相对路径 |
| `retain_days` | 当前保留天数 |
| `min_free_gb` | 当前磁盘空间阈值 |

---

### 5.2 `sensor_fps` — 传感器帧率汇总

**模块：** `Sensor`  
**时机：** 每 `sensor_fps_interval_sec` 秒一条（默认 5s）  

**附加字段：**

| 字段 | 说明 |
|------|------|
| `interval_sec` | 统计窗口长度（秒） |
| `lidar210_fps` | 210 雷达发布帧率 |
| `lidar210_ts` | 210 最新一帧时间戳（秒，传感器时间） |
| `lidar211_fps` | 211 雷达发布帧率 |
| `lidar211_ts` | 211 最新时间戳 |
| `camera_left_fps` | 左相机发布帧率 |
| `camera_left_ts` | 左相机最新时间戳 |
| `imu_fps` | GNSS/INS（IMU 协议）接收帧率 |
| `imu_ts` | IMU 最新时间戳 |
| `fused_cloud_fps` | 融合点云（发往 SLAM/泊位）发布帧率 |
| `fused_cloud_ts` | 融合点云最新时间戳 |

**说明：** 帧率在窗口内计数后清零；某路传感器未接入时，对应 `_fps` 为 `0`，`_ts` 可能为 `0`。

**示例：**

```json
{"ts":"2026-05-20T06:32:05.000Z","level":"INFO","tid":12345,"module":"Sensor","event":"sensor_fps","interval_sec":5,"lidar210_fps":9.8,"lidar210_ts":1716189123.456,"lidar211_fps":10.0,"lidar211_ts":1716189123.458,"camera_left_fps":24.2,"camera_left_ts":1716189123.460,"imu_fps":100.0,"imu_ts":1716189123.461,"fused_cloud_fps":9.6,"fused_cloud_ts":1716189123.459}
```

---

### 5.3 `node_lifecycle` — 节点生命周期

**时机：** 各模块初始化、启动、停止  

**附加字段：**

| 字段 | 说明 |
|------|------|
| `state` | 状态：`ready` / `start` / `stop` |

**已记录的 module 与典型状态：**

| `module` | `ready` | `start` | `stop` |
|----------|---------|---------|--------|
| `Application` | — | 主窗口初始化完成 | 程序退出 |
| `SensorPublisher` | Topic 发布器就绪 | — | — |
| `PreProcessor` | 预处理节点 Init | 预处理线程 Start | 预处理 Stop |
| `BridgeDetection` | 桥洞节点 Init | 检测线程 Start | 检测 Stop |
| `BerthDetection` | 泊位节点 Init | 检测线程 Start | 检测 Stop |
| `PerceptionPipeline` | — | 点击「检测开关」开启流水线 | 关闭流水线 |
| `DloSlam` | SLAM 节点 init 成功 | SLAM 建图 Start | SLAM Stop |

**示例：**

```json
{"ts":"2026-05-20T06:30:01.100Z","level":"INFO","tid":8888,"module":"BerthDetection","event":"node_lifecycle","state":"start"}
```

---

### 5.4 `berth_result` — 泊位检测结果

**模块：** `BerthDetection`  
**时机：** 泊位被检测到，且几何相对上次记录**发生明显变化**时（去重，避免每帧刷屏）  

**去重阈值（与 UI 检测日志一致）：**

- 中心位移 &lt; 0.15 m、长宽 &lt; 0.20 m、角度 &lt; 1°、开口边不变 → 视为未变化，不写盘

**附加字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `timestamp` | number | 检测帧时间戳（秒） |
| `detected` | bool | 是否检测到泊位 |
| `berth_count` | number | 泊位数量（`detected=true` 时） |
| `berths` | array | 各泊位详情 |

**`berths[]` 每项：**

| 字段 | 说明 |
|------|------|
| `index` | 泊位序号，从 1 开始 |
| `cx`, `cy` | 中心坐标（米，与算法/显示同一平面坐标系） |
| `w`, `l` | 宽、长（米） |
| `angle_deg` | 朝向角（度） |
| `opening_edge` | 开口边编号 0～3，-1 表示未知 |
| `corners` | 四角顶点 `[{x,y}, ...]`，共 4 点 |

**四角顶点顺序（局部系旋转至世界系）：**

索引 0～3 对应局部矩形四角（宽 `w`、长 `l`）：  
`(-w/2,-l/2)` → `(w/2,-l/2)` → `(w/2,l/2)` → `(-w/2,l/2)`。

**丢失检测：** 若此前有泊位、当前帧未检测到，会写一条 `detected: false` 的事件。

**示例：**

```json
{"ts":"2026-05-20T06:35:10.200Z","level":"INFO","module":"BerthDetection","event":"berth_result","timestamp":1716189310.2,"detected":true,"berth_count":2,"berths":[{"index":1,"cx":12.3,"cy":45.6,"w":10.1,"l":10.4,"angle_deg":166.8,"opening_edge":2,"corners":[{"x":7.1,"y":40.2},{"x":17.0,"y":41.0},{"x":16.2,"y":51.0},{"x":6.3,"y":50.2}]}]}
```

---

### 5.5 `bridge_result` — 桥洞检测结果

**模块：** `BridgeDetection`  
**时机：** 桥洞检测结果相对上次记录变化时（中心/宽高变化 &lt; 0.2 m 视为相同）  

**附加字段：**

| 字段 | 说明 |
|------|------|
| `timestamp` | 检测帧时间戳（秒） |
| `detected` | 是否检测到桥洞 |
| `center_x`, `center_y`, `center_z` | 桥洞中心三维坐标（米，`detected=true` 时） |
| `width_m`, `height_m` | 桥洞宽、高（米） |

**示例：**

```json
{"ts":"2026-05-20T06:36:00.000Z","level":"INFO","module":"BridgeDetection","event":"bridge_result","timestamp":1716189360.0,"detected":true,"center_x":25.1,"center_y":-3.2,"center_z":4.5,"width_m":8.0,"height_m":6.5}
```

---

### 5.6 `disk_space` — 磁盘空间

**模块：** `SystemFileLogger`  
**时机：** 程序启动后首次检查；之后每 `disk_check_interval_sec` 秒（默认 600s）  

**附加字段：**

| 字段 | 说明 |
|------|------|
| `free_gb` | 日志所在卷剩余空间（GB） |
| `total_gb` | 该卷总容量（GB） |
| `root` | 卷根路径（如 `D:/`） |

---

### 5.7 `log_cleanup` — 旧日志清理

**模块：** `SystemFileLogger`  
**时机：** 启动时（若 `cleanup_on_startup=true`）；磁盘空间不足时；定期磁盘检查时若低于阈值  

**附加字段：**

| 字段 | 说明 |
|------|------|
| `reason` | `retain_days`（按天过期）或 `low_disk_space`（空间不足） |
| `deleted_files` | 本次删除文件数 |
| `freed_bytes` | 释放字节数 |
| `deleted_names` | 被删文件名数组 |

**示例：**

```json
{"ts":"2026-05-20T06:30:00.050Z","level":"INFO","module":"SystemFileLogger","event":"log_cleanup","reason":"retain_days","deleted_files":2,"freed_bytes":41943040,"deleted_names":["system_2026-05-01.jsonl","system_2026-05-02.jsonl"]}
```

---

## 6. 旧数据与保留策略

系统日志**仅自动清理 `logs/system_*.jsonl`**，不会删除 SLAM 地图（`maps/`）、用户保存文件或其他业务数据。

### 6.1 按天数保留

- 参数：`retain_days`（默认 14 天）
- 删除文件名日期 **早于**「今天 − retain_days」的日志文件
- **当天文件始终保留**（即使磁盘空间紧张）

### 6.2 按磁盘空间紧急清理

- 当 `free_gb` &lt; `min_free_gb` 时，从**日期最早**的 `system_*.jsonl` 起依次删除
- 直到剩余空间 ≥ `min_free_gb`，或仅剩当天文件无法继续删

### 6.3 清理可追溯

每次清理均写入 `log_cleanup` 事件，便于确认删除了哪些文件、释放了多少空间。

## 7. Python 读取与分析示例

需安装：`pandas`（可选 `matplotlib` 绘图）。

```python
import pandas as pd
import json

path = "logs/system_2026-05-20.jsonl"
df = pd.read_json(path, lines=True)

# 传感器帧率曲线
fps = df[df["event"] == "sensor_fps"].copy()
fps["ts"] = pd.to_datetime(fps["ts"])
fps.set_index("ts")[["lidar211_fps", "imu_fps", "fused_cloud_fps"]].plot(title="Sensor FPS")

# 泊位检测事件
berths = df[df["event"] == "berth_result"]
for _, row in berths.iterrows():
    if row.get("detected"):
        print(row["ts"], row["berth_count"], "berths")

# 展开泊位四角（单泊位示例）
row = berths[berths["detected"] == True].iloc[-1]
for b in row["berths"]:
    corners = b["corners"]
    print(f"berth #{b['index']} angle={b['angle_deg']}° corners={corners}")

# 磁盘空间
disk = df[df["event"] == "disk_space"]
disk["ts"] = pd.to_datetime(disk["ts"])
disk.set_index("ts")["free_gb"].plot(title="Free disk (GB)")

# 节点启停时间线
life = df[df["event"] == "node_lifecycle"][["ts", "module", "state"]]
print(life)
```

按事件过滤的推荐方式：始终使用 `event` 字段，不要依赖 `module`  alone。

## 8. 常见问题

**Q：关闭系统日志？**  
A：在 `config.json` 中设置 `"system_log": { "enabled": false }`，重启程序。

**Q：日志太大怎么办？**  
A：减小 `retain_days`、增大 `sensor_fps_interval_sec`，或提高 `min_free_gb` 让系统更积极清理旧文件。

**Q：时间戳用 UTC 还是本地？**  
A：记录字段 `ts` 为 UTC；业务字段如 `timestamp`、`imu_ts` 等为传感器/算法使用的秒级时间，与数据源一致。

**Q：Release 包日志在哪？**  
A：与 `PointCloud.exe` 同级的 `logs/` 目录（除非在 `config.json` 中改为绝对路径）。
