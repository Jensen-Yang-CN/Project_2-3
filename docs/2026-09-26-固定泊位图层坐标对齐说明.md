# 2026-09-26 固定泊位图层坐标对齐说明

## 本次问题

老师提供的 `泊位检测完整地理信息` 使用的局部 ENU 原点，与统一离线地图
`Mergedclouds_enu_optimized.slammap` 的 ENU 原点不同。因此直接绘制泊位框时，
泊位方向虽然正确，但整体位置会产生平移。

## 本次处理

程序加载离线地图后，读取地图内的地理锚点；加载固定泊位库时，使用泊位记录中的
经纬度和地图锚点，通过 WGS84 ECEF → ENU 转换计算泊位在地图坐标系中的位置，再对
本地显示层统一施加平移补偿。当前数据计算出的平移约为东向 `+5.7024 m`、北向
`-75.4937 m`，实际运行时会根据加载的地图锚点动态计算，不写死该数值。

## 影响范围

- 只调整程序端固定泊位显示图层，使其与离线地图和实时点云使用同一坐标系。
- 泊位检测算法、实时点云、SLAM 建图及历史地图投递流程不变。
- UDP 投递中的泊位原始坐标单元不变，接收端协议和 Ship.exe 无需同步修改。
- 11003 条原始记录仍按原逻辑归并为 11 个泊位簇；本次只修正显示位置。

## 验证记录

使用当前泊位 JSON 与统一地图锚点计算，11 个归并泊位的补偿平移标准差小于 1 cm，
说明它们共享同一个固定原点偏移，适合用统一平移完成显示对齐。
