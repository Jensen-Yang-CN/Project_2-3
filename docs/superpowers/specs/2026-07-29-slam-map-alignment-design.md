# SLAM 地图对齐与失真修正设计

## 目标

让新建 SLAM 地图使用有效 GNSS/INS 的 ENU 航向初始化，船体图标与轨迹显示真实船体位姿，并阻止错时的 210/211 点云和无效导航姿态进入配准链路。

## 已确认根因

1. `LidarGnssSlam` 首帧固定使用单位位姿，丢弃了匹配 GNSS/INS 的初始航向，因此地图不是 ENU/正北对齐。
2. `MultiLidarWidget` 将 `pose_lidar` 直接作为船体位姿绘制，未消除 210 雷达到船体的外参偏移。
3. `RadarFusionManager` 中 `forcePass=true` 绕过 100 ms 同步限制，运动时可能把旧 211 帧并入当前 210 帧。
4. SLAM 等待 GICP 完成期间不消费 IMU Topic；350 Hz 输入配合 64 帧环形缓存会丢失中间导航样本。
5. SLAM 只用经纬度非零判断 GNSS/INS，有效标志、范围和非有限数未校验。
6. 外参文件必须按 UTF-8 读取并通过 Qt/JSON 加载测试；旧矩阵需要保持不变。

## 设计

### 地图坐标

输入点云始终保持在 210 雷达坐标系。首个可处理点云使用同一时间附近的 GNSS/INS 推导 `T_map_lidar`，作为 SLAM 初始位姿；后续仍使用导航相对增量预测并由 GICP 修正。这样不改变点云配准的局部几何，只补回此前被丢弃的初始 ENU 航向。

### 船体显示

SLAM 状态继续发布 `T_map_lidar`。界面绘制船体时使用：

`T_map_body = T_map_lidar * inverse(T_body_lidar)`

地图关键帧仍按 `T_map_lidar` 变换，不对地图点重复施加船体外参。

### 雷达与导航时序

210 继续作为主时间戳。211 只有在与主帧时间差不大于 100 ms 时才参与融合；没有合格 211 时允许发布 210 单雷达点云。GICP 等待循环每 50 ms 消费一次 IMU Topic，导航最大时间差收紧到 250 ms。

### 导航有效性

进入 SLAM 的 GNSS/INS 必须满足：时间戳和全部数值有限、时间戳为正、经纬度范围合法且非全零、yaw/pitch/roll 有效标志全部为真。

### 配置

以 UTF-8 和 Qt 加载测试验证 `calibration.json`。检查确认文件本身合法，因此不重写矩阵；保持用户要求回退后的旧 210/211 外参数值不变，并确认当前构建运行目录使用同一份配置。

## 验证

- 单元测试验证：过期雷达帧被拒绝、有效帧被接受、初始地图位姿保留 GNSS/INS 航向、雷达位姿可还原船体位姿、无效导航被拒绝。
- `radar_update_tests` 验证运行时 `calibration.json` 可成功加载。
- 完整 Debug 构建验证所有修改可链接。
- 旧地图不删除；修复效果通过新建地图观察，既有已变形地图不做离线重算。
