# SLAM 地图持久化与启动恢复设计

## 目标

升级现有地图文件格式，使地图文件能够保存：

- 地图格式版本；
- SLAM 使用的首个有效 GNSS 地理锚点；
- 每个关键帧的编号、时间戳、`T_map_lidar` 位姿；
- 每个关键帧的局部坐标系点云。

程序下次启动后，自动恢复最近一次成功保存或手动加载的新版地图，并由保存的关键帧重新生成累计点云地图后显示在界面上。

## 方案比较

### 方案 A：单文件版本化归档（采用）

使用新的 `.slammap` 单文件格式，将元数据、地理锚点、关键帧位姿和关键帧点云放入同一个归档。

优点：

- 文件完整，复制一个文件即可迁移地图；
- 可以通过魔数和版本号可靠校验；
- 保存成功后再更新“最近地图”记录，启动恢复行为稳定；
- 后续可以继续增加会话信息、标定摘要和位姿图。

代价：

- 文件可能较大；
- 读取时需要限制关键帧数、单帧点数和总点数，避免损坏文件造成异常内存分配。

### 方案 B：目录式地图

每张地图使用一个目录，包含 `metadata.json`、关键帧位姿表和多个点云文件。

优点是便于人工检查和增量更新；缺点是容易出现文件缺失或目录复制不完整，本次不采用。

### 方案 C：继续扩展旧 `.pcd`

在原文件尾部追加地理锚点和关键帧数据。

改动看似较少，但旧格式没有魔数和版本号，兼容判断不可靠，而且扩展名与实际格式不符，本次不采用。

## 文件格式

新版扩展名为 `.slammap`，使用显式字段序列化，禁止直接写入 C++ 结构体内存，避免编译器对齐和类型大小变化导致文件失效。

文件按以下顺序组织：

1. 固定魔数；
2. 格式主版本与次版本；
3. 地图坐标系标识（当前为 ENU）；
4. 地理锚点有效标记；
5. 锚点时间戳、纬度、经度和高程；
6. 关键帧数量；
7. 对每个关键帧保存：
   - 关键帧编号；
   - 时间戳；
   - 平移 `x/y/z`；
   - 单位四元数 `qx/qy/qz/qw`；
   - 点数量；
   - 每个点的 `x/y/z/intensity`。

加载时检查魔数、版本、数值有限性、四元数有效性、关键帧数量、单帧点数、总点数和文件是否完整。未知主版本拒绝读取并给出明确错误。

原有 `.pcd` 自定义二进制文件继续支持手动加载，但它只能恢复累计点云，没有地理锚点和可重建关键帧。旧格式不会被当作自动恢复的首选地图。

## 地理锚点来源

`DloSlamNode` 在向 `LidarGnssSlam` 喂入 GNSS/INS 时，记录同一个数据流中的首个有效 GNSS：

- 纬度、经度必须在合法范围内且不能同时为零；
- 高程当前协议没有真实来源时保存为 `0`；
- 时间戳保存该 GNSS/INS 报文时间戳；
- 地图坐标系标记为 ENU。

这样保存的锚点与 SLAM 内部建立 ENU 原点时使用的数据一致，不使用界面层单独计算的轨迹原点代替。

## 运行时数据流

### 建图与保存

1. `DloSlamNode` 产生关键帧，并保存本次会话的地理锚点。
2. `MultiLidarWidget` 接收关键帧用于实时累计显示，同时保留关键帧数据。
3. 点击“保存地图”时，从 SLAM 节点获取当前关键帧和地理锚点，写入临时文件。
4. 文件完全写入并关闭后，用原子替换方式生成最终 `.slammap`。
5. 保存成功后更新最近地图记录。

### 手动加载

1. 文件选择器优先显示 `.slammap`，同时允许选择旧 `.pcd`。
2. 新版文件读取为地图归档。
3. 界面清空旧地图，逐关键帧执行 `world_point = T_map_lidar * local_point`，生成累计地图。
4. 恢复最后一个关键帧位姿和关键帧轨迹，切换到 SLAM 地图视图。
5. 加载成功后更新最近地图记录。

### 启动自动恢复

1. `AppConfig` 加载完成且 OpenGL 控件已创建后执行恢复。
2. 首先读取最近一次成功保存/加载的新版地图路径。
3. 若记录不存在或目标文件失效，扫描 `maps` 目录并选择修改时间最新的 `.slammap`。
4. 加载成功后直接切换到 SLAM 地图模式并记录日志。
5. 若没有地图或地图损坏，程序继续正常启动，仅记录原因，不弹出阻塞对话框。

最近地图记录存放在 `maps/last_slam_map.txt`，内容为规范化绝对路径。只有地图保存或加载完全成功后才更新。

## 界面状态

加载新版地图后：

- 显示由关键帧重新累计得到的点云，不显示单独保存的预览点云；
- 恢复最后一个关键帧对应的船体位置，用于初始居中；
- 恢复关键帧轨迹；
- 地图按钮切换为已启用状态；
- 不自动启动 PCAP、SLAM 算法或信息投递。

自动恢复的历史地图与新建图会话相互隔离。用户点击“SLAM 建图”开始新会话时，先清空历史显示地图，再接收新关键帧，避免两张地图在未配准的情况下直接叠加。

## 错误处理与安全限制

- 保存采用临时文件加原子提交，失败时不破坏已有地图；
- 对关键帧数、单帧点数和总点数设置硬上限；
- 读取失败时保持当前界面地图不变；
- 自动恢复失败不影响程序主功能；
- 地理锚点无效时仍可保存和显示本地地图，但文件中明确标记锚点无效；
- 旧 `.pcd` 手动加载后可以显示，但不能伪造关键帧或地理锚点。

## 测试

新增地图持久化测试，覆盖：

1. 新版文件保存后可完整恢复地理锚点、关键帧位姿和点云；
2. 由恢复的关键帧重新累计得到预期世界坐标点；
3. 地理锚点无效的地图仍可保存和加载；
4. 旧 `.pcd` 文件仍可加载；
5. 错误魔数、未知版本、截断文件和异常点数被拒绝；
6. 最近地图记录优先，其失效时回退到目录中最新 `.slammap`；
7. 保存失败不会更新最近地图记录；
8. 项目现有测试与完整构建继续通过。
