# PCAP USV 时间跳转、0.5x 回放与暂停快照设计

**日期：** 2026-08-05  
**状态：** 用户已确认交互设计，等待书面规格复核

## 1. 目标

在现有 PCAP 原始时间戳播放器上完成三项调整：

1. 时间跳转可直接输入 USV 位置姿态面板显示的本地时间，例如 `2026-06-10 14:28:34.145`；
2. 增加 `0.5x` 慢速回放；
3. 点击暂停时，保存暂停时刻对应的 210、211 完整原始点云，以及左右两路完整解码图像，用于复现和调试算法错误。

## 2. 时间语义

USV 面板中的时间来自 `IMUParsedData::timestamp`。离线 PCAP 模式下，`ImuWorker::processNavPacket` 已将该值替换为 PCAP 抓包时间戳，界面再通过 `QDateTime::fromMSecsSinceEpoch(..., Qt::LocalTime)` 转为本地时间。因此 USV 面板时间与 PCAP 原始 Unix 时间戳属于同一时间轴，无需建立额外偏移。

“时间跳转”输入框同时接受：

- 本地时间：`yyyy-MM-dd HH:mm:ss.zzz`，例如 `2026-06-10 14:28:34.145`；
- 原始 Unix 秒：例如 `1770171582.123456`，作为兼容输入。

本地时间使用系统本地时区解析，与 USV 面板显示方式一致。输入框、有效范围提示和跳转完成日志优先展示本地时间，同时附带 6 位小数的 Unix 时间戳，便于精确核对。由于 USV 面板只显示毫秒，本地时间输入定位到该毫秒对应的 Unix 时间，读取器仍选择第一个 `packet_timestamp >= target_timestamp` 的包。

无效格式、无效日期或超出 PCAP 范围时，只提示错误，不停止或改变当前播放。

## 3. 0.5x 回放

播放器允许的速度范围由 `1.0~4.0` 扩展为 `0.5~4.0`。工具栏倍速按钮按以下顺序循环：

`0.5x → 1x → 2x → 4x → 0.5x`

程序默认仍使用配置文件中的 `default_speed`；配置值小于 `0.5` 时收敛到 `0.5`，大于 `4.0` 时收敛到 `4.0`。0.5x 只改变播放器放包时钟，不修改 UDP 载荷、PCAP 原始时间戳或检测算法输入。

时间跳转的隐藏预热仍固定为 4x；到达目标后恢复用户跳转前选择的速度，包括 0.5x。

## 4. 暂停时刻定义

`PcapngReader` 记录最后一个已经通过播放时钟、准备进入解析链路的抓包记录时间戳。用户点击“暂停”时：

1. 先暂停播放器，阻止后续抓包记录继续放行；
2. 读取最后放行记录的精确 PCAP 时间，作为本次暂停目标时间；
3. 保留固定 300 ms 的下游收尾窗口，让已经进入 RTP、雷达 SDK 和工作线程队列的数据完成组帧；
4. 收尾窗口内不恢复读取器，不会引入暂停目标之后的新 PCAP 包；
5. 为 210、211、左相机和右相机分别选择与暂停目标时间最接近的完整帧。

帧选择只接受时间戳不晚于暂停目标的帧，并从中选择时间差最小者。每一路与暂停目标的最大允许差值为 0.5 秒。缓存只保留每一路的最新帧和当前暂停请求的最佳候选，不建立大量图像或点云历史队列，避免显著增加内存。

## 5. 快照数据来源

- 210 点云：`Ls400Worker 210::cloudReady` 输出的完整单雷达帧；
- 211 点云：`Ls400Worker 211::cloudReady` 输出的完整单雷达帧；
- 左图像：左侧 H.265 `VideoWorker::frameReady` 解码后的原分辨率图像；
- 右图像：右侧 H.265 `VideoWorker::frameReady` 解码后的原分辨率图像。

点云不使用融合点云，也不使用泊位算法过滤后的点云。图像不叠加桥梁检测框，保存的是解码原图。

快照功能只在离线 PCAP 播放从“播放”切换到“暂停”时触发。点击“继续”不会再次保存；在线接收模式和时间跳转内部的隐藏预热不会触发暂停快照。

## 6. 文件格式与目录

根目录固定为程序可执行文件旁的：

`pause_snapshots`

四路数据分别保存到：

- `pause_snapshots/210/<时间戳>.pcd`
- `pause_snapshots/211/<时间戳>.pcd`
- `pause_snapshots/camera_left/<时间戳>.png`
- `pause_snapshots/camera_right/<时间戳>.png`

文件名使用暂停目标的本地时间，采用 Windows 安全格式：

`yyyyMMdd_HHmmss_zzz`

例如：`20260610_142834_145.pcd`。同一暂停时刻的四个文件使用完全相同的基本文件名。重复在同一时刻保存时允许覆盖同名文件，因为数据来源和目标时间相同。

PCD 使用 binary 格式，字段为 `x y z intensity`：三个 32 位浮点坐标和一个 8 位无符号强度。写入时去掉 `M_PointXYZI` 的内存填充字节，生成符合 PCD 规范的紧凑数据。PNG 使用解码图像原始尺寸，无检测标注。

磁盘写入在后台任务中执行，并先创建所需目录，避免大点云写盘阻塞 Qt 界面。

## 7. 完整性与错误处理

只有以下条件全部满足，才报告“暂停快照保存成功”：

- 210、211 两路点云候选均非空；
- 左右两路图像候选均非空；
- 四路候选与暂停目标时间差均不超过 0.5 秒；
- 四个目标文件均写入成功。

若某一路缺失或超差，不把不完整集合报告为成功，并在检测日志与状态栏明确列出缺失/超差的数据源。为了保留已获得的调试信息，满足自身有效性条件的其他数据仍可写盘，但日志必须标明本次集合不完整。

文件无法创建、PCD 写入失败或 PNG 编码失败时，显示具体文件路径和错误原因。后台任务完成后通过 Qt 队列回到 GUI 线程更新日志与状态栏。

## 8. 组件边界

### 8.1 播放时间工具

新增独立、可测试的时间解析与格式化函数：

- 解析本地 USV 时间或 Unix 秒；
- 格式化本地显示范围；
- 生成 Windows 安全快照文件名。

### 8.2 `PcapPlaybackController` / `PcapngReader`

- 控制器支持 0.5x；
- 读取器以原子值记录最后放行的 PCAP 时间戳，供 GUI 线程在暂停时读取；
- 不在读取器内保存文件或接触界面对象。

### 8.3 暂停快照收集与写入

新增独立快照组件：

- 保存四路最新完整帧；
- 在暂停请求期间更新最接近目标时间的候选；
- 校验 0.5 秒容差；
- 将点云写为 binary PCD、图像写为 PNG；
- 返回逐文件保存结果和完整性摘要。

### 8.4 `MainWindow`

- 在现有四路数据槽中把原始帧交给快照组件；
- 播放切换到暂停时启动一次快照请求；
- 300 ms 后复制候选并投递后台写盘；
- 显示保存成功、集合不完整或写盘失败信息；
- 不改变检测开关、SLAM 开关及时间跳转状态机。

## 9. 测试与验收

### 自动测试

- 0.5x 将 100 ms 抓包间隔调度为约 200 ms；
- 配置速度正确收敛到 `0.5~4.0`；
- 本地 USV 时间与 Unix 时间戳双向转换一致；
- 非法日期、非法数字和超范围输入被拒绝；
- 快照文件名不含 Windows 非法字符；
- 候选选择使用最接近且不晚于暂停目标的帧；
- 缺失一路或时间差超过 0.5 秒时集合标记为不完整；
- binary PCD 头、点数、字段类型与二进制载荷正确；
- 四路有效数据可以生成两份 PCD 和两份 PNG。

### 集成验收

- 输入 USV 面板时间可跳到对应位置；
- 0.5x 下视频、点云和检测持续正常更新；
- 检测开关打开时，0.5x 和暂停/继续不会导致算法失效；
- 点击暂停后，程序目录出现四个同名时间戳文件；
- PCL 工具可读取 210/211 PCD，图像查看器可打开左右 PNG；
- 日志显示暂停目标时间、四路实际帧时间和各自时间差；
- 时间跳转隐藏预热不会错误生成暂停快照；
- 历史 SLAM 地图仍不默认显示。
