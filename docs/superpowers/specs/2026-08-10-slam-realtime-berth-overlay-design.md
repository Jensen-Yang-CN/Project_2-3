# SLAM 地图实时泊位框叠加设计

**日期：** 2026-08-10  
**状态：** 用户已确认采用推荐方案

## 目标

点击“检测开关”后，泊位算法继续对当前 `210/211` 融合点云运行一次；点云模式显示雷达局部坐标泊位框，SLAM 地图模式同时显示经过时间同步和坐标转换的实时泊位框。泊位框不写入 SLAM 地图文件，也不永久累计。

## 当前问题

`BerthDetectionNode` 已持续发布 `BerthMeasureResult`，但结果坐标位于 210 雷达局部坐标系。`MultiLidarWidget::paintGL()` 在 `m_showSlamMap` 为真时显式跳过 `drawBerthOverlays()`，因为 SLAM 点云和轨迹位于 map 世界坐标系，直接绘制局部框会造成框随船移动或固定在错误位置。

## 架构

### 泊位几何变换

新增无状态的泊位几何变换工具，将以下数据由 `T_map_lidar` 转换到 SLAM map 坐标：

- 泊位中心、角度和所有实体边；
- U 型开口边编号及 `visible_edges`；
- 实时最高点、次高点和对应数组；
- 锚点总线、调试线和调试 ROI；
- 实时/盲区回显来源字段保持不变，因此颜色仍分别为黄绿色和蓝色。

现有 `RealtimeBerthCoordinateLibrary` 改为复用同一个几何变换工具，避免两套开口边和边元数据转换规则产生差异。

### 时间同步

新增 UI 线程内使用的 `SlamBerthOverlaySynchronizer`：

- 保存最近 200 个 SLAM `T_map_lidar` 位姿；
- 保存最近 100 个非空泊位结果；
- 在泊位结果或 SLAM 位姿任一到达时，寻找时间差不超过 0.25 秒的最新匹配；
- SLAM 处理即使晚于泊位检测，后到的位姿也能补齐投影；
- 空泊位结果立即清除已投影框并丢弃旧待匹配结果，避免旧框复现；
- 关闭检测或 PCAP 跳转时清除结果；SLAM 地图清空时同时清除位姿历史；
- 投影结果相对最新 SLAM 时间超过 8 秒时不再显示。

所有信号均以 `Qt::QueuedConnection` 进入 GUI 线程，因此同步器不增加锁。

### 渲染

`MultiLidarWidget` 保留两份结果：

- `m_berthResult`：210 局部坐标，用于普通点云模式；
- 同步器输出：SLAM map 世界坐标，用于 SLAM 地图模式。

`drawBerthOverlays` 接受明确的结果参数。普通点云模式沿用现有时间有效性和边高度；SLAM 俯视模式使用世界坐标几何及固定绘制高度，防止把雷达局部边高误当作 map 高程。U 型泊位依旧只绘制三条实体边，不绘制 `opening_segment`。

## 生命周期

- 检测打开：算法运行，两个视图分别消费同一检测结果的局部/世界表达。
- 切换点云与 SLAM：不重复启动算法，只切换使用的坐标结果。
- 检测关闭：局部和 SLAM 泊位框同时清除。
- PCAP 时间跳转：清除泊位待匹配队列与已投影框，等待新时间线数据。
- SLAM 清图/重启：清除 SLAM 位姿历史和世界泊位框。
- 保存 SLAM 地图：不保存泊位框。

## 验收标准

1. 90 度旋转和指定平移后，泊位中心、实体边和锚点均落在正确 map 坐标。
2. 实时框保持黄绿色，坐标库回显保持蓝色，U 型开口没有封口线。
3. 同时间戳数据可以立即投影；先到的泊位结果在 SLAM 位姿后到时可以补画。
4. 超过 0.25 秒的位姿不用于投影，超过 8 秒的投影结果不显示。
5. 空检测结果、关闭检测、时间跳转和 SLAM 清图均不会留下旧框。
6. 点云模式现有泊位显示、播放器、SLAM、桥梁检测和投递协议不发生回归。
