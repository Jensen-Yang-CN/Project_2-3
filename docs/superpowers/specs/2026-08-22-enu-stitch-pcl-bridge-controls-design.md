# ENU 地图拼接与近点点云桥梁检测融合设计

## 目标

在不覆盖现有双路相机传统桥梁检测、泊位检测、SLAM 和 PCAP 播放功能的前提下：

1. 把 `qiao-pointcloud.zip` 中的近点融合点云桥梁/桥墩/障碍物检测语义合并到当前工程；
2. 将原来的统一“检测开关”拆成独立的“桥梁检测”和“泊位检测”；
3. 让“桥梁检测”同时控制传统双路相机桥梁检测和新增点云检测；
4. 让“泊位检测”只控制泊位检测及其 SLAM/实时点云回显；
5. 地图拼接以 WGS84 地理锚点换算到统一 ENU 为唯一全局基准，避免时间接缝或 ICP 产生大幅二次刚体偏移。

## 已确认的现状

- SLAM 输入 GNSS/INS 后，以第一条有效导航数据为 WGS84 锚点，累计位置使用 ENU，姿态使用绝对导航航向。
- `.slammap` 文件头声明 ENU，并保存每张地图的经纬度、高程锚点与 ENU 关键帧位姿。
- 当前三张实测地图中，第二张地图在完成锚点换算后又被时间接缝算法平移 `15.455 m`、偏航 `-3.759°`。该二次修正会使已处于同一 ENU 定义下的地图失去统一地理基准。
- 当前“检测开关”用单个 `m_perceptionDetectEnabled` 同时门控桥梁和泊位数据，无法独立关闭。
- 新点云模块使用五雷达融合点云，提供桥梁、桥墩、100 m 内障碍物、距离与时序跟踪结果。

## 地图拼接设计

### 坐标基准

第一张地图的 WGS84 锚点作为输出地图锚点。其他地图锚点先由 WGS84 转 ECEF，再投影到第一张地图的 ENU，得到唯一允许施加的地图间平移：

```text
T_base_source = Translation(E_source, N_source, U_source)
T_base_keyframe = T_base_source * T_source_keyframe
```

不再默认叠加时间接缝刚体修正或 ICP 旋转/平移。

### 重叠处理

- 时间完全被已有地图覆盖：跳过整张重复地图。
- 时间部分重叠：只删除时间不晚于当前地图末尾的重复关键帧；新增尾部仍按地理锚点直接变换，不施加接缝修正。
- 时间不重叠：保留全部关键帧，按锚点直接拼接。
- 日志显示每张地图的 ENU 锚点偏移、时间重叠、裁剪帧数和追加帧数。

这样既消除同一时刻的重复帧，也不会为了视觉上临时贴合而破坏地图的经纬度一致性。原 ICP/时间接缝实现保留为显式诊断能力，但默认加载路径禁用。

## 检测按钮与数据流设计

### 桥梁检测

开启后同时启用：

1. 左右相机传统桥梁检测与视频叠加层；
2. 新增五雷达融合点云桥梁、桥墩和障碍物检测；
3. 点云语义渲染：桥梁红色、桥墩绿色、障碍物橙色边界；
4. 检测日志按最多每秒一次输出距离、方位与接近速度。

关闭后停止向传统桥梁节点提交雷达/相机帧，不再启动新的点云任务，并清除两路视频桥梁层和点云语义层。

### 泊位检测

开启后只把融合点云发布到泊位 Topic，保持实时点云和 SLAM 地图中的泊位框、盲区回显和泊位投递功能。

关闭后停止泊位输入并清除实时/SLAM 泊位结果，不影响桥梁检测、视频、融合点云显示或 SLAM。

### 总线生命周期

检测节点在首次开启任一检测后启动，并保持到程序退出；按钮只门控各自输入。这避免泊位节点停止后取消订阅、再次开启却收不到数据的旧生命周期问题。

## 点云算法调度与坐标约定

- 新增检测只接收 `RadarFusionManager::fusedCloudReady` 的五雷达融合点云。
- 使用一个持久化 `PclClusterPreview` 保留跨帧轨迹和桥下状态。
- 同一时刻最多运行一个后台任务；算法忙时丢弃新帧，不阻塞 GUI、PCAP 调度、SLAM 或泊位检测。
- PCAP 跳转或桥梁开关关闭后重置算法状态，防止旧时间线跟踪结果回显。
- 当前工程船体坐标为 `+X` 船艏、`+Y` 左侧；渲染船体半长 `6.0 m`、半宽 `2.5 m`。新算法据此使用 `shipHalfExtentX=6.0`、`shipHalfExtentY=2.5`，不照搬候选文件中与当前工程相反的 `X=2/Y=5`。

## 构建与兼容性

- 添加 `ENABLE_PCL_PERCEPTION`，默认开启；依赖当前已经为 SLAM 配置的 PCL 运行时。
- 采用语义合并，不用候选版 `mainwindow`、`MultiLidarWidget` 或 `CMakeLists.txt` 覆盖当前文件。
- 保留当前相机桥梁、泊位、SLAM、快进/暂停、双 32 线雷达、投递和地图持久化功能。
- 不把新模块生成的桥洞 ROI 转发给旧视觉桥梁节点，避免两套算法循环耦合。

## 验证标准

1. ENU 拼接测试证明默认路径只施加锚点平移，部分重叠只裁剪、不产生额外偏航或平移。
2. 两个按钮可独立开关，桥梁关闭不影响泊位，泊位关闭不影响视觉与点云桥梁。
3. 新点云算法使用正确船体坐标，后台任务不积压。
4. 当前测试套件全部通过，Debug 主程序完整编译通过。
5. 使用三张现有 `.slammap` 输出诊断，第二张地图不再出现 `15.455 m/-3.759°` 的二次时间接缝修正。
6. 使用压缩包测试 PCAP 进行实机界面验证；若当前环境无法自动操作 Qt 界面，提供明确的人工复核步骤和日志依据。
