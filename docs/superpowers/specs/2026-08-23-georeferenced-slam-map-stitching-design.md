# 基于逐关键帧地理约束的 SLAM 地图拼接设计

## 1. 背景与目标

现有 `.slammap` v2.0 只保存一个地图地理锚点。各次独立 SLAM 虽然都以 ENU 为坐标轴，但地图内部关键帧仍包含各自累计的激光配准误差。仅用单个起点锚点只能统一原点，不能消除整段轨迹上的漂移；扩大 ICP 搜索范围还会把码头中相似的平行结构错误匹配。

本次改造目标是：

- 新地图保存每个关键帧对应的 GNSS/INS 雷达 ENU 参考位姿；
- 使用多点地理约束平滑校正关键帧累计漂移；
- 地图进入同一 ENU 后，仅允许小范围、有明确质量改善的静态结构配准；
- 完成对齐后再做三维体素去重，消除重合区域的重复显示；
- 继续读取 v2.0 地图，但不对缺少证据的旧地图施加大幅修正；
- 程序启动时仍不自动加载历史地图。

## 2. 方案选择

采用“离线地理校正 + 受限配准”的方案，不改变现有实时 SLAM 主滤波结构。

不采用以下方案：

- 不用 GNSS 瞬时位姿强制覆盖实时 SLAM 位姿，避免导航噪声直接写入局部地图；
- 不依靠大范围 ICP，因为本数据中的平行码头结构已产生约 19.7 米的错误候选；
- 不依靠大体素隐藏重影，因为这会删除相邻真实结构并降低地图分辨率。

## 3. 数据模型

在 `SlamKeyframe` 中新增可选的地理参考：

```cpp
struct SlamGeoPoseReference {
    bool valid = false;
    double timestamp = 0.0;
    double sync_error_sec = 0.0;
    Eigen::Isometry3d pose_lidar_enu = Eigen::Isometry3d::Identity();
};
```

每个关键帧保留两套位姿：

- `pose`：SLAM 输出的 `T_map_lidar`，保证局部点云连续性；
- `geo_reference.pose_lidar_enu`：同一时间戳附近由 GNSS/INS 和雷达外参得到的原始 ENU 参考位姿，用于离线漂移约束。

地理参考与地图头部的 `SlamGeoAnchor` 使用同一个 ENU 原点。

## 4. 关键帧地理参考采集

`LidarGnssSlam` 已经为每帧雷达插值 GNSS/INS 里程计。本次增加线程安全的“最近已处理导航参考”输出，内容包括参考位姿、雷达时间戳以及最近原始导航样本的时间差。

`DloSlamNode` 创建关键帧时读取该参考，仅当以下条件同时满足才标记有效：

- 参考时间戳与当前雷达帧一致；
- 原始导航样本时间差不超过现有 `max_gnss_sync_sec`；
- 位姿矩阵全部为有限数值。

无有效 GNSS/INS 的关键帧仍可保存，但不会参与地理漂移校正。

## 5. `.slammap` v2.1 文件格式

文件主版本保持 `2`，次版本升级为 `1`。每个关键帧元数据在点数之后增加固定长度的地理参考记录：

- 有效标记；
- 参考时间戳；
- 同步误差；
- ENU 雷达位姿的平移和四元数。

兼容规则：

- v2.1：读取并校验逐关键帧地理参考；
- v2.0：正常读取，所有关键帧的地理参考标记为无效；
- 高于当前支持次版本的文件：明确拒绝，避免按错误布局解析；
- 新保存文件统一写为 v2.1；
- 加载失败不能改变调用方原有地图对象。

保存已校正地图时，关键帧 `pose` 是校正后的位姿，地理参考保持不变。再次加载时残差接近零，因此不会产生重复修正。

## 6. 多点地理漂移校正

新增独立组件 `SlamMapGeoCorrector`，在地图加载后、地图间拼接前运行。

处理流程：

1. 从有效关键帧计算二维 SE(2) 残差：
   `C_i = T_geo_i * inverse(T_slam_i)`；
2. 拒绝同步误差超限、非有限位姿和相对邻域中明显跳变的 GNSS 残差；
3. 对平移残差和展开后的偏航残差做时间窗口鲁棒中值平滑；
4. 在有效地理关键帧之间按时间线性插值平滑修正；
5. 对有效区间之外仅使用最近端点修正，不外推漂移趋势；
6. 将平滑的 `C(t)` 左乘到每个关键帧 `pose`；
7. 输出有效约束数、拒绝数、修正中位数、最大修正量和校正后残差。

校正至少需要 3 个分布在有效时间跨度内的地理关键帧。少于 3 个时保持原地图不变，并记录原因。

为避免 GNSS 抖动破坏局部结构：

- 使用 5 个地理关键帧的滑动中值；
- 平移残差相邻跳变超过 5 米或偏航残差跳变超过 5 度时，将当前参考视为离群点；
- 修正曲线必须连续；
- 不修改关键帧局部点云，只修改其世界位姿。

## 7. 地图间拼接

每张输入地图先独立完成地理漂移校正，再执行现有锚点到统一 ENU 的转换。

v2.1 地图的点云精配准只负责消除导航系统的会话级小偏置：

- 默认只允许 XY 平移，不改变 ENU 航向；
- 最大修正 3 米；
- 初值搜索步长缩小到 1 米；
- 候选贴近搜索边界时拒绝；
- 必须同时满足双向匹配率、鲁棒 RMSE 和相对锚点质量改善门限；
- 任何失败都回退到“逐关键帧地理校正 + 锚点 ENU”，不得采用未经证明的大幅修正。

v2.0 旧地图使用相同的 3 米安全上限，但日志明确显示“缺少逐关键帧地理约束”。当前两份旧地图若需要最高精度，必须用对应原始 PCAP 重新生成 v2.1 地图。

## 8. 三维体素去重

地图完成空间对齐后，在显示点云构建阶段进行确定性的三维体素去重：

- 默认体素边长为 0.3 米；
- 使用 XYZ 三维体素，不能只用 XY，防止删除同一墙面上的不同高度点；
- 按地图加载顺序处理，同一体素已有点时保留先加载地图的点；
- 原始关键帧及保存文件不删除点，避免不可逆数据损失；
- 日志输出输入点数、显示点数和删除的重复点数。

## 9. 数据流

```text
GNSS/INS → 插值导航雷达位姿 ─┐
                              ├→ SlamKeyframe(pose + geo_reference)
融合点云 → 实时 SLAM pose ───┘
                              ↓
                      .slammap v2.1
                              ↓
              单地图逐关键帧地理漂移校正
                              ↓
                 地理锚点转换到统一 ENU
                              ↓
                  小范围质量门控精配准
                              ↓
                   0.3 m 三维体素去重
                              ↓
                         界面显示
```

## 10. 日志与错误处理

加载或拼接时显示：

- 文件格式版本；
- 关键帧总数和有效地理参考数；
- 地理参考离群点数量；
- 漂移修正的中位值、最大平移和最大偏航；
- ICP 候选、质量改善和接受/拒绝原因；
- 体素去重前后点数。

旧地图不是错误文件，不中止加载；但必须明确提示其只能使用锚点和保守配准。无有效锚点的多地图仍拒绝自动拼接。

## 11. 测试与验收

自动化测试覆盖：

- v2.1 地理参考保存/加载往返一致；
- v2.0 固定样本仍可加载，地理参考为无效；
- 不支持的次版本被拒绝；
- 合成线性漂移和缓慢偏航漂移校正后，关键帧参考位置误差小于 0.2 米；
- 单个 GNSS 跳点不会扭曲整张地图；
- 少于 3 个地理参考时不修改地图；
- 19 米一类的大范围或边界假匹配被拒绝；
- 对齐后同一 0.3 米三维体素只输出一个显示点，不同高度点仍保留；
- 单地图加载、多地图拼接、保存重载和主程序构建通过；
- 启动时不自动加载历史地图。

## 12. 交付边界

本次交付能消除由“只保存单个锚点”导致的软件结构性问题，并阻止大范围错误配准。GNSS/INS 自身的绝对测量误差不能由软件凭空消除；会话级小偏置由严格质量门控配准补偿。旧 v2.0 文件缺少逐关键帧数据，无法达到重新解析 PCAP 后 v2.1 地图的精度。
