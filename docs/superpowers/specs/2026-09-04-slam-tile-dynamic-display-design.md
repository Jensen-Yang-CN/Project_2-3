# 统一 ENU 离线地图只读分块动态显示设计

## 1 背景与目标

当前离线地图加载流程会完整读取一张或多张 `.slammap`，执行地理校正和拼接，再遍历全部关键帧构建一个大的显示点云。即使最终显示点数限制为 150 万，加载、校正、拼接和显示重建阶段仍会持有完整地图及多个临时副本，地图范围和分辨率增大后会出现启动慢、内存占用高和界面响应变差的问题。

本次改造实现统一 ENU 后的只读分块动态显示：

- 保持现有 `.slammap` 文件不变；
- 一张地图沿用自身 ENU，选择多张地图时沿用现有地理校正和拼接结果，统一到第一张地图的 ENU；
- 首次加载时生成可删除、可重建的分块缓存；
- 后续根据当前视野和 USV 位置只加载需要的 Tile；
- 磁盘读取和数据解码在后台执行，OpenGL 资源只在界面线程更新；
- 离线 Tile 地图作为独立背景层，不改变实时 SLAM、USV 轨迹和泊位检测回显。

地图错位、雷达时间同步、SLAM 轨迹优化、在线地图更新以及定位算法使用 Tile 地图不属于本次范围。

## 2 方案选择

采用派生式分块地图缓存方案。

不直接修改 `.slammap`，也不只为现有文件添加关键帧侧边索引。现有 `.slammap` 按关键帧组织，不适合高效空间随机读取。首次加载时把已统一到基准 ENU 的世界点云转换为按空间组织的 Tile 缓存，后续直接读取缓存索引和可见 Tile。

不采用运行时纯内存临时切块，因为该方式每次仍需全量读取和重建，不能解决启动时间和内存峰值问题。

## 3 用户行为

继续使用现有“加载地图”入口：

1. 选择一张 `.slammap` 时，使用该地图的 ENU 锚点生成分块缓存；
2. 选择多张 `.slammap` 时，先沿用现有地理校正与拼接流程，再以第一张地图锚点为统一 ENU 原点生成一套缓存；
3. 缓存不存在或失效时，在后台执行一次完整转换，并在日志和状态栏显示阶段；
4. 缓存有效时，只读取清单和当前区域 Tile，不再完整读取源地图；
5. 加载另一组地图时立即清除旧 Tile、旧 GPU 缓存和未完成请求；
6. 源文件大小、修改时间、选择顺序、Tile 参数或缓存格式版本变化时，旧缓存自动失效；
7. 原始 `.slammap` 始终只读，不被转换流程修改。

Tile 地图激活时，“保存地图”不重新组装完整 `.slammap`。保存功能继续服务实时 SLAM 会话，避免只读显示模式重新产生全量内存峰值。

程序启动时仍不自动恢复历史离线地图。

## 4 缓存目录和格式

缓存位于地图目录下：

```text
maps/
├── source.slammap
└── tiled_cache/
    └── <cache-key>/
        ├── manifest.json
        ├── trajectory.bin
        ├── L0/
        │   └── tile_<x>_<y>.tilebin
        ├── L1/
        │   └── tile_<x>_<y>.tilebin
        └── L2/
            └── tile_<x>_<y>.tilebin
```

缓存键由以下内容按顺序计算：

- 每个源文件的规范绝对路径；
- 文件大小和最后修改时间；
- 用户选择顺序；
- 缓存格式版本；
- Tile 尺寸和各级 LOD 体素尺寸。

`manifest.json` 保存：

- 格式魔数和主次版本；
- 基准地图地理锚点；
- 统一 ENU 地图 XY 和 Z 边界；
- Tile 尺寸；
- LOD 体素尺寸；
- 源地图指纹；
- 轨迹文件信息；
- 每个 Tile 的编号、LOD、文件相对路径、ENU 包围盒、点数、字节数和校验值。

`tilebin` 使用版本化二进制格式。文件头保存魔数、版本、Tile 编号、LOD、Tile ENU 原点、包围盒、点数和记录尺寸。每个点保存 Tile 局部 `float x/y/z` 和强度，读取后恢复为统一 ENU 坐标。局部坐标避免大型港区地图使用全局 `float` 时精度下降。

缓存通过临时目录构建，全部文件写入并校验成功后再原子替换最终目录。转换失败时不留下可被误认为有效的缓存。

## 5 分块与 LOD

默认参数：

```text
Tile 尺寸             50.0 m
L0 体素               1.0 m
L1 体素               0.3 m
L2 体素               0.1 m
预取环数              1
卸载环数              2
RAM 缓存预算          512 MB
GPU 显示点预算        1500000
视图变化防抖          120 ms
```

世界点先由关键帧局部坐标通过关键帧 ENU 位姿变换，再按固定全局网格划分 Tile：

```text
tile_x = floor((enu_x - grid_origin_x) / tile_size)
tile_y = floor((enu_y - grid_origin_y) / tile_size)
```

Tile 使用半开区间 `[min, max)`，边界点只属于一个 Tile。每个 LOD 使用全局体素编号做确定性去重，避免相邻 Tile 边界重复和不同转换批次结果不一致。

LOD 用途：

- L0：大范围总览；
- L1：正常 SLAM 地图浏览，保持当前 0.3 米显示去重尺度；
- L2：靠泊区域近距离放大查看。

LOD 根据视图单位像素覆盖范围和 GPU 点预算选择。切换采用滞回阈值，防止滚轮缩放临界位置反复切换。

## 6 区域选择

俯视模式使用 `m_viewPanX`、`m_viewPanY`、`m_bevRange` 和窗口宽高比计算可见 ENU 矩形。

- Active Set：与可见矩形及半个 Tile 安全边界相交的 Tile；
- Prefetch Set：Active Set 外扩一圈 Tile；
- Unload Set：超出 Active Set 两圈且不再被请求的 Tile。

存在有效 USV 位姿时，将船周围必要区域与视口 Active Set 取并集，避免船体、轨迹和泊位框附近背景被卸载。

三维透视模式第一版使用当前视图中心与视距估算保守圆形区域，不实现完整视锥裁剪。

鼠标拖动和滚轮缩放后通过 120 毫秒单次定时器更新请求，连续交互只保留最后一次区域计算。

## 7 异步加载与状态管理

新增 `SlamTileMapManager`，职责包括：

- 加载和校验 Manifest；
- 根据视口计算 Active、Prefetch 和 Unload 集合；
- 在后台线程读取与解码 Tile；
- 按实际字节数管理 RAM LRU 缓存；
- 固定 Active Tile，禁止其被 LRU 淘汰；
- 发出 Tile 就绪和 Tile 移除事件；
- 输出缓存命中率、加载耗时、常驻内存和当前 LOD 日志。

每次打开新地图生成递增的请求代号。后台结果返回时必须同时匹配地图实例代号、请求代号和 Tile 当前所需状态，否则直接丢弃，防止旧地图和旧视口数据迟到后混入当前显示。

后台线程只产生不可变点数据。OpenGL VBO 的创建、更新和销毁全部在 `MultiLidarWidget` 所在线程执行。

## 8 OpenGL 图层

离线地图从单个 `m_slamMapCloud` 和单个反复写入的 `m_slamVbo` 改为每个常驻 Tile 持有独立 GPU 缓冲区。绘制时遍历当前可见 Tile，不把所有 Tile 再次拼接成一个大 `QVector`。

保留现有独立图层：

- 实时累计关键帧层；
- 当前 SLAM 扫描层；
- USV 船体和轨迹；
- 泊位检测世界坐标回显。

离线 Tile 层只替换当前“加载归档后重建整张显示点云”的路径。实时 SLAM 建图仍可使用原有累计关键帧逻辑。

打开新地图时先清除原离线 Tile 层，加载失败则显示明确错误，不恢复或混合旧地图。

修改文件：

- `config/config.json`：增加默认配置；
- `src/slam/SlamMapLoadTask.h/.cpp`：复用现有统一 ENU 拼接结果并调度一次性缓存构建；
- `src/gui/mainwindow.h/.cpp`：加载状态、缓存命中和只读地图生命周期；

现有总线 `MapRepository` 在本期保持不变。它是内存地图仓库预留结构，尚未接入 `.slammap` 加载链路，不与只读离线显示管理器混用。

## 10 错误处理

- Manifest 版本、锚点、边界或 Tile 列表无效时拒绝加载；
- Tile 文件不存在、校验失败或点数异常时跳过该 Tile并记录错误，不阻塞其他区域；
- Active Tile 加载失败时保留黑色空区并允许下一次区域刷新重试；
- Prefetch 失败不弹出阻塞提示；
- RAM 预算不足以容纳全部 Active Tile 时选择更粗 LOD，仍不足时按距视图中心从近到远加载并记录预算告警；
- 缓存转换失败时保留源 `.slammap` 和当前实时功能，不发布半成品缓存；
- 程序关闭时停止接受新请求，后台结果不得访问已销毁窗口或 OpenGL 控件。

## 11 测试和验收

自动化测试覆盖：

- 正负 ENU 坐标的 Tile 编号计算；
- 半开边界归属和全局体素去重；
- 单地图及已拼接地图锚点保持一致；
- Manifest 和 Tile 二进制往返；
- 损坏、截断、错误版本和错误校验值被拒绝；
- 源文件或参数变化导致缓存失效；
- LOD 点数随体素增大单调不增加；
- 视口到 Active、Prefetch、Unload 集合计算；
- Active Tile 不被 LRU 淘汰；
- 内存按字节预算淘汰；
- 旧地图和旧请求的迟到结果被拒绝；
- 新地图加载时旧 Tile 集合立即清空；
- 现有地图 IO、拼接、地理校正、显示、泊位和 PCAP 测试继续通过。

人工验收：

1. 首次选择 `.slammap` 能完成缓存转换并显示；
2. 第二次加载相同地图直接命中缓存，不再全量重建；
3. 拖动地图时相邻 Tile 提前出现，界面不因磁盘读取停止响应；
4. 缩放时自动切换 LOD，不发生明显跳位或连续闪烁；
5. 新地图不会和上一张地图混合；
6. 同一视口与旧版全量显示的几何位置一致，差异不超过所选 LOD 的体素尺度；
7. 常驻 RAM 不超过配置预算，GPU 点数不超过 150 万；
8. 原始 `.slammap` 内容和修改时间不变；
9. 实时 SLAM、USV 轨迹和泊位框继续正常显示；
10. `PointCloud.exe` Release 构建成功，全部相关 CTest 通过。
