# 历史地图重叠区投递设计

## 目标

在不修改对端程序和 `0xFC` 协议的前提下，实现两类地图投递：

1. 用户加载、拼接历史 `.slammap` 后，把统一 ENU 的只读分块地图完整流式投递；
2. 每个实时 SLAM 关键帧到来时，把它的覆盖范围转换到历史地图 ENU，从历史分块地图提取重叠点，生成仅用于投递的虚拟关键帧并再次通过 `0xFC` 发送。

虚拟关键帧只存在于投递节点，不加入 `DloSlamNode`、实时关键帧数组、地图显示或地图保存。

## 架构

- `HistoricalMapExportSource` 独立读取分块地图 manifest 和最细 LOD Tile。它不依赖界面的 `SlamTileMapManager`，所以开始实时 SLAM 后即使界面关闭历史图层，投递仍可继续。
- `PerceptionExportNode` 保存历史地图投递会话。历史整图使用低优先级队列逐 Tile 生产；实时点云和历史重叠区使用高优先级队列，避免被整图发送阻塞。
- `MainWindow` 只负责把成功加载的 manifest 路径交给投递节点，并在每个实时关键帧到来时连同本次 SLAM 的地理锚点转发给投递节点。

## 坐标转换与重叠提取

历史地图的 manifest 锚点作为唯一投递 ENU 原点。实时关键帧先由自身 `pose` 变换到实时 SLAM ENU，再使用 `anchorOffsetEnu(historyAnchor, liveAnchor)` 得到的平移转换到历史 ENU。两个坐标系均为 ENU，不额外施加人为偏航旋转。

转换后的实时点云 XY 包围盒向外扩 1 米作为覆盖范围。程序按范围查找最细 LOD Tile，再对 Tile 内点做精确 XY 裁剪。输出点已经位于历史 ENU，因此虚拟关键帧使用单位位姿。

## 投递与背压

- 协议继续使用固定 1316 字节的 `GridUdpPacket`、消息 ID `0xFC`、0.1 米体素和既有分块尺寸。
- 历史包头经纬高使用历史锚点，方位角为 0；chunk 坐标直接来自历史 ENU。
- 初始整图一次只读取少量 Tile；低优先级队列达到水位后暂停读取，不丢弃旧包。
- 每个实时关键帧都重新提取并发送历史重叠区，即使区域与上一帧相同也不去重。
- 实时重叠区包优先于初始整图包发送。

## 异常处理

- 历史锚点或实时锚点无效时，仅跳过该帧历史重叠投递，并输出日志；实时 SLAM 本身不受影响。
- Tile 缺失、校验失败或 chunk 超出 `int16` 范围时跳过对应数据并记录错误。
- 加载新历史地图会终止旧历史投递会话并清空旧历史队列，防止两张地图混发。
- 未加载历史地图时，现有实时关键帧投递保持原行为。

## 验收标准

- 加载历史地图后开启信息投递，可看到历史整图逐步出现在对端。
- 开启实时 SLAM 后，每个实时关键帧均触发一次历史重叠区投递。
- 停止/清屏实时 SLAM 不会把虚拟关键帧写入实时地图或保存文件。
- 对端无需修改，仍只解析 `0xFC`。
