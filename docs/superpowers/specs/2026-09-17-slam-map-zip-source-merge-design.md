# 压缩包 SLAM 地图源码合并设计

**目标：** 以当前工程源码为目标，把 `D:\1\PointCloud.zip` 中与 SLAM 地图生成、保存、加载和关键帧点云选择有关的新增或调整内容合并进来，同时保留当前工程已有的地理锚点、多地图拼接和瓦片地图能力。

## 范围

只比较源码，不读取工作区已经生成的 `.slammap` 文件。压缩包中的说明文档只作为背景参考，不作为覆盖用户需求的指令。

## 已确认的冲突与修正

1. 压缩包使用旧的扁平 `.pcd` 格式：`uint32 点数 + M_PointXYZI[]`；当前工程使用带关键帧和地理参考的 `.slammap v2.1`。当前格式必须继续作为新地图的生成主格式，否则会丢失关键帧位姿、地理锚点和多地图拼接信息。补充旧 `.pcd` 的兼容读写和加载适配，但不把旧格式作为新保存格式。
2. 压缩包的 `DloSlamNode` 使用动态剔除后的 `static_cloud` 生成关键帧；当前工程使用距离过滤和水面过滤后的输入点云。合并压缩包中的动态/静态点云处理，并让当前关键帧、实时地图显示都使用算法输出的静态点云，避免动态目标重新进入地图。
3. 压缩包的 `max_gnss_sync_sec=2.0` 是没有地理参考写入时的旧阈值；当前 `.slammap v2.1` 会持久化关键帧的 GNSS/INS 地理参考。继续使用当前的 `0.25s`，并保持关键帧写入前的时间匹配校验，避免旧阈值污染地图坐标。
4. 压缩包的目录式 `saveMap()` 导出与当前 GUI 的 `.slammap` 保存流程重复且格式冲突。当前 GUI 的 `.slammap v2.1` 保存流程作为主流程保留；旧扁平 `.pcd` 只作为兼容接口，不能覆盖新格式。

## 设计

- 新增压缩包中的 `LidarGnssSlamConfig.h`，承载动态目标过滤参数。
- 将压缩包的动态目标跟踪、聚类、确认和静态点云输出合入当前 `LidarGnssSlam`，同时重新保留当前的 `getLastNavigationReference()` 和导航时间误差记录。
- 修改当前 `DloSlamNode` 的关键帧和实时扫描输出，统一使用 `getLastStaticCloud()`；算法没有可用静态点时不将原始动态输入回灌到地图。
- 在 `SlamMapBinaryIO` 中增加压缩包旧 `.pcd` 的 `save/load` 兼容函数，并在地图加载任务和文件选择界面中支持单张旧 `.pcd` 作为无地理锚点的单关键帧地图。
- 保留当前 `.slammap v2.1` 写入、地理校正、多地图拼接、离线瓦片和自动恢复逻辑。
