# 泊位区域高密度离线地图投递设计

## 目标

只优化历史离线地图的 0xFC 点云投递：保存的泊位附近使用 `0.1 m` 栅格，非泊位区域使用 `0.3 m` 栅格，以提高泊位附近点云可见密度，同时控制整图的 UDP、磁盘和接收端栅格负担。

不修改实时地图投递、泊位检测算法、泊位 0xFB 数据、坐标转换、开口方向和 Ship 端程序。

## 当前实现基线

- `config/config.json` 的离线 Tile LOD 当前包含 `1.0/0.3/0.05 m`。
- `PerceptionExportNode` 当前历史地图包固定按 `0.05 m` 重新栅格化。
- `HistoricalMapExportSource` 当前加载 manifest 后只选择全图最细 LOD，因此泊位和背景不能区别选择。
- Tile 缓存键包含源文件、Tile 大小和 LOD 列表；改变 LOD 列表会触发新缓存。

全图统一改成 `0.1 m` 会比当前 `0.05 m` 更粗，不符合“泊位附近看上去点云更多”的目标，因此不采用。

## 方案

### 1. Tile 生成

保留多级 Tile 结构，生成 `1.0/0.3/0.1 m` 三个 LOD。每个 Tile 仍按当前 `50 m` 边长、原有 ENU 坐标和 manifest 格式保存。历史缓存键必须包含新的 LOD 列表，旧缓存不可复用。

### 2. 泊位区域判定

从 `manifest.berths` 读取已保存的 `SlamMapBerth`。根据泊位中心、长度、宽度和角度计算旋转矩形的 XY 包围盒，并增加固定安全边界；只要 Tile 的 XY 范围与任一泊位 ROI 相交，就视为泊位 Tile。

没有保存泊位记录时，不猜测区域，整图使用 `0.3 m` 背景 LOD。固定泊位 JSON 不参与 Tile ROI 判定，避免静态库改变历史点云投递行为。

### 3. 历史投递选择

`HistoricalMapExportSource` 不再只保存一个全局 `finest_lod_`：

- 泊位 ROI 相交 Tile 选择 `0.1 m` LOD。
- 其他 Tile 选择 `0.3 m` LOD。
- 若某一 LOD 缺失，按可用的更细/更粗 LOD 安全回退，并在日志中报告选择结果。

整图初始投递和实时关键帧重叠区域都复用同一套 Tile 选择规则，保证历史显示前后一致。0xFB 泊位仍从原有历史记录/检测结果发送，不做任何坐标或开口转换。

### 4. 兼容与缓存

- `manifest` 格式不新增必须字段，继续使用现有 `berths` 和 `tiles`；这样旧 `.slammap` 可以重新生成新 Tile 缓存。
- 旧缓存因 LOD 列表不同而自动失效；若用户手工保留旧缓存，加载任务应检测到不匹配并重建。
- `.pcd` 没有泊位记录，因此只使用 `0.3 m` 背景 LOD，不影响其兼容加载。
- 当前本地 OpenGL SLAM 地图显示不改，实时地图和泊位检测显示不改。

## 测试标准

1. Tile 配置解析仍能读取 `1.0/0.3/0.1 m`，缓存键随 LOD 改变。
2. 构造一个含两个泊位和背景点的 manifest：泊位相交 Tile 选 0.1 m，背景 Tile 选 0.3 m。
3. 无泊位 manifest 全部选择 0.3 m，不崩溃、不访问不存在的 Tile。
4. 历史整图投递和重叠虚拟关键帧使用相同选择结果。
5. 现有历史地图、泊位协议和实时投递测试保持通过。
6. 运行时日志能够区分“泊位高密度 Tile”和“背景 Tile”，方便与 Ship 端点云数量对照。

## 回滚

恢复 `config/config.json` 的 LOD 列表并删除新缓存目录即可回到原有全局最细 LOD 投递；代码开关不改变实时地图和泊位结果路径。
