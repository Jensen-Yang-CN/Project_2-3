# 固定 ENU 离线地图坐标对齐设计

## 目标

加载 `Mergedclouds_enu_optimized.slammap` 时，将之后 PCAP 回放产生的实时 SLAM 数据统一转换到该地图已经使用的 ENU 坐标系，使本地黄色历史点云与绿色实时点云在同一坐标系叠加。

## 已确认事实

1. `Mergedclouds_enu_optimized.slammap` 的地图点云已经是 ENU 坐标，不应再次套用 `map_to_enu`。
2. 该文件中的关键帧没有有效的逐帧 GNSS/INS 参考，不能依赖首个关键帧自动推导 `map -> ENU` 变换。
3. `D:/1/yuanshibanben/georeference(1).json` 给出的固定矩阵为：

   `T_map_to_enu = [0.343116876975, 0.938955843305, 0.025154185683, 8.062556171207; -0.939256930598, 0.343214516898, 0.000462291067, -1.210357550253; -0.008199210788, -0.023784863103, 0.999683476521, -1.547567040739; 0, 0, 0, 1]`。

## 方案

只按文件名识别固定离线地图：加载文件名为 `Mergedclouds_enu_optimized.slammap`（大小写不敏感，允许同名副本所在目录不同）时：

- canonical 历史地图跳过普通地图的地理校正步骤；历史地图点云、历史泊位记录保持读取后的 ENU 坐标，不做二次变换。
- 将固定 `T_map_to_enu` 写入实时对齐状态，并标记对齐已就绪，不等待不存在的关键帧导航参考。
- 实时关键帧位姿、实时里程计位姿和实时扫描点只应用一次 `T_map_to_enu`。
- 关键帧点云仍保留在雷达局部坐标，由现有地图合并流程使用变换后的位姿变换一次，避免点云重复变换。
- 保存当前实时地图时沿用现有逻辑，清除已转换关键帧的原始地理参考，避免重新加载时再次校正。

加载其他 `.slammap` 或 `.pcd` 时保持当前逻辑不变。

## 不在范围内

- 不修改泊位检测算法、泊位开口方向、固定泊位图层或 UDP 投递协议。
- 不改动接收端 `Ship.exe`。
- 不对历史地图点云重新采样、重建或移动。

## 诊断信息

加载固定地图后输出一条简短日志，说明已启用固定 ENU 对齐；普通地图继续输出原有加载信息。

## 验证

- 单元测试验证固定矩阵能把一个已知实时位姿和点变换到预期 ENU 坐标，且历史点不被变换。
- 单元测试验证固定矩阵仅应用一次，`transformKeyframe` 不修改局部点云。
- 运行 `git diff --check`。
- 使用现有可用的 MinGW 直接编译并运行坐标变换测试；完整工程构建若仍被旧的外部 vcpkg 路径缓存阻塞则单独报告。
