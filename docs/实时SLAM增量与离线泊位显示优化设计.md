# 实时 SLAM 增量与离线泊位显示优化设计

## 目标

只针对本次需求做三项小范围调整：

1. PCAP 回放期间，本地 SLAM 视图持续显示关键帧增量，而不是只显示初始占据栅格。
2. 桥梁检测、泊位检测按钮文字反映当前开关状态。
3. 加载离线 `.slammap` 后，本地视图显示固定泊位库中的全部泊位。

## 方案

- 保留 OctoMap、UDP 投递和检测节点不变。启用 OctoMap 时，UI 仍接收原有占据栅格，同时额外订阅 `slam/keyframe` 和 `slam/scan_cloud`；关键帧进入独立的实时点云层，避免覆盖历史地图或改变投递数据。
- 在 `MultiLidarWidget` 中增加固定泊位覆盖层。加载 `.slammap` 成功后读取项目已有的固定泊位 JSON，转换为本地 `usv::BerthMeasureResult`，只用于绘制，不写入实时检测结果、不写入地图保存内容。
- 检测按钮在构造、点击、统一状态同步和算法管线停止时统一设置文字：关闭为“桥梁检测/泊位检测”，开启为“停止桥检/停止泊检”。

## 影响边界

- 不修改 `PerceptionExportNode` 的 UDP 协议、实时泊位投递、历史地图投递和固定泊位发送逻辑。
- 不修改桥梁、泊位算法本身及历史地图坐标变换。
- 新增逻辑只影响本地 SLAM 视图和按钮显示。

## 验证

- 静态回归测试检查 OctoMap 分支仍订阅关键帧/扫描、固定泊位图层只在离线地图加载路径接入、按钮文字包含开启/停止两组状态。
- 运行相关单元测试和 `git diff --check`；完整构建若再次触发已有 GCC8 `std::filesystem` 问题，单独记录，不扩大本次修改范围。
