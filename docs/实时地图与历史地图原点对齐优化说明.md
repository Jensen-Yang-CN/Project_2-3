# 实时地图与历史地图原点对齐优化说明

## 实现效果

加载 `Mergedclouds_enu_optimized.slammap` 后，PCAP 回放产生的绿色实时点云会与黄色历史点云使用同一个 ENU 坐标系叠加显示，实时船位不再出现“朝向正确但整体平移”的情况。

## 实现方式

1. 历史 `slammap` 中的点云保持原坐标，不再重复变换。
2. 实时 SLAM 首个有效关键帧到达后，先根据关键帧的 `pose` 和 GNSS/INS 参考位姿计算本次会话的动态 `map → ENU` 旋转与局部平移。
3. 分别记录历史地图锚点和本次 PCAP 回放的实时 GNSS 锚点。
4. 使用 `anchorOffsetEnu()` 计算“实时 ENU 原点相对历史 ENU 原点”的平移量，并将该平移补到实时 `map → ENU` 变换中。
5. 后续实时里程计、实时扫描点云和关键帧统一使用补偿后的变换；历史黄色点云不做修改。
6. 在实时锚点和坐标变换建立前，暂不把未对齐关键帧写入历史地图，避免产生混合坐标。

## 涉及代码

- `src/gui/MultiLidarWidget.cpp/.h`：保存历史锚点、接收实时锚点，并完成实时地图原点平移补偿。
- `src/gui/mainwindow.cpp`：将 DLO SLAM 会话首个有效 GNSS 锚点传给地图显示组件。
- `src/slam/SlamRealtimeMapAlignment.h`：提供实时变换重新基准化函数。
- `tests/slam_realtime_map_alignment_tests.cpp`：验证实时变换叠加历史 ENU 原点偏移后的结果。

泊位检测、Ship 接收端协议和历史地图点云内容均未参与此次坐标补偿修改。
